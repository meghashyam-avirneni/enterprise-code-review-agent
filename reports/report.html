Executive Summary

This report documents the controls used to evaluate generated code-review results. The system does not treat model confidence, schema validity, or successful tool execution as proof of correctness.

The review separates model output, deterministic validation, schema/tool validation, routing evidence, provenance, conflicts, timeouts and human-review requirements.

Core principle: Evaluate generated output rather than automatically trusting it because it is confident, structured, schema-valid or tool-generated.

2. Schema and Tool Validation

The review explicitly distinguishes schema/tool validity from semantic correctness.

  • A schema-valid response can still contain an incorrect value.
  • Deterministic quantities are independently validated.
  • Model-generated arithmetic is not automatically trusted.
  • Discrepancies are preserved rather than silently overwritten.
Validation rule: Schema-valid does not mean factually correct.

3. Missing and Null Values

The extraction workflow distinguishes missing, null, zero, empty and unavailable values.

A missing value is not silently converted to zero, and unavailable evidence is not converted into a factual assertion.

Evidence: 02-schema-tool-validation/extract-run.txt

4. Normalization

Equivalent representations are normalized before comparison where appropriate. The original/source representation remains available for auditability.

Normalization is therefore used to make valid comparisons and is not used to fabricate or alter evidence.

5. Supply-Chain Investigation

Provenance

Material claims retain source, metric, value, date, scope and conflict information.

Conflicting Metrics

When sources disagree, both values remain visible with their provenance. Conflicting metrics are not silently merged into a single unsupported value.

Dated Claims

Time-sensitive claims are associated with relevant dates. Historical evidence is not presented as current evidence without appropriate date context.

6. Timeout and Unavailable Sources

A source that cannot be retrieved within the permitted time is represented as TIMEOUT / UNAVAILABLE.

A timeout is not interpreted as proof that the underlying claim is false. The source remains visible for audit and follow-up.

Evidence: 03-supply-chain/timeout-run.txt

7. Human Review

Human review remains appropriate when:

  • confidence is poorly calibrated;
  • evidence sources conflict;
  • deterministic validation disagrees with model output;
  • required evidence is unavailable;
  • interpretation is ambiguous; or
  • a time-sensitive claim cannot be verified.

Final Assessment

The report package addresses the identified reviewer concerns by explicitly separating confidence, structural validity, deterministic validation, provenance, conflicts, time-sensitive claims and unavailable evidence.

The key controls are:

  1. Confidence is evaluated against observed correctness.
  2. Deterministic checks independently validate checkable results.
  3. Schema validity is separated from semantic validity.
  4. Missing values remain explicit.
  5. Normalization preserves source information.
  6. Conflicting metrics remain visible.
  7. Timeouts remain explicit unavailable states.
  8. Time-sensitive claims include date context.
  9. Ambiguous cases remain eligible for human review.
